# Rojo 8.0.0 — jonasvq fork

Independent fork based on Rojo 7.7.1, focused on reliable filesystem-driven
Roblox development, rapid editor/AI changes and observable Studio synchronization.
This is a jonasvq release, not an official rojo-rbx release.

## Highlights

- Resilient rapid file creation, rewrites, renames, moves and deletions, repaired
  watches and immutable queued changes.
- Faithful property resets, references, script identity, MeshParts, TweenInfo
  attributes and isolated serialized-model fallback.
- Optional project V2, reusable sync-rule defaults and class-based filesystem/
  Studio property authority.
- Confirmed Source persistence receipts, guarded topology repair and opt-in
  saved-instance adoption.
- Existing-place updates, watched syncback, Open Cloud uploads, mapped Studio
  output, consent-scoped plugin integration and automatic debugger plans.
- Runnable tutorial, cookbook, coding-agent guide and verified Windows setup.

## Changes

- Honor class-specific property authority during explicit syncback: retain filesystem-owned properties and native source bytes while exporting Studio-owned descendants. Reject changed filesystem structure and unsafe reference preservation before writes; keep existing format and layout restrictions.

- Preserve Studio-owned class properties during initial connection and live file updates through negotiated `classAuthorityV1`. Retain instance/reference identities, require explicit review for authority changes or destructive replacement, and protect serialized/topology recovery. Legacy clients refuse incompatible sessions.

- Add optional inherited `syncAuthority` class policies. Explicit matching policies block legacy writes and Source-only receipts; check current project state before legacy mutations. Preserve nested overrides, embedded/CSV authority, offline build/stdin/syncback and JSONC destinations.

- Add validated reusable class-authority types with exact/nearest-superclass precedence and strict configuration validation.

- Repair moved/detached managed instances, reconstruct uncontested deleted subtrees and rebind exact copies under opt-in adoption before live updates. Preserve references, unknown descendants, selection and Undo; refuse ambiguous or dirty-source recovery before mutation and retain reconnect review for dirty copies.

- Add shared `syncRules.defaults` properties, attributes, tags and metadata, with independent routing, explicit override precedence and per-key removal masks. Preserve rule authority through syncback without per-file default copies; retain JSONC paths and reject lossy binary property columns. Apply live sync policy metadata without replacing healthy instances.

- Add opt-in adoption of saved, untracked Studio instances during live sync after unique readable-property/subtree/reference checks. Preserve identities and unknown descendants; stop ambiguous conflicts before mutations or fallback. Serialization-only values remain unchanged and explicitly unverified. Preserve manual edits when refusing a patch.

- Confirm opt-in two-way Source writes with bounded correlated persistence receipts and file readback; preserve newer local edits, expose conflicts for explicit review, and require confirmation after uncertain reconnects. Legacy servers report queued-only writes.

- Extract reusable project tree, path and reflected value types into the local `rojo-project-types` crate, without filesystem, CLI, network or place-serializer dependencies. Preserve existing `librojo` exports and exact Rust type identity through re-exports.

- Make CLI and HTTP dependencies optional through a default-enabled `cli` feature. `default-features = false` retains the build, project, snapshot, syncback and wire-data APIs without the executable, transport or embedded-plugin build; standard CLI builds remain enabled.

- Recognize `init.project.json/jsonc` directory entries only with explicit V2, report conflicting entries, retain default-project priority and explicit-file selection, and refresh directory roles after live alias/version changes without changing syncback destinations.

- Add optional project `$version` 1/2. Explicit V2 defaults to modern scripts and inherited unknown-descendant preservation; unversioned projects retain their defaults, explicit overrides win, and reload/syncback retain the chosen semantics without migrating files.

- Add opt-in loopback automatic debugger plans with per-connection Studio consent, managed-source versions, bounded native stacks/locals/table inspection, typed numeric filters/evaluation and predetermined steps; revoke points/callbacks on lifecycle changes and expose bounded immutable reports.

- Add the Windows `open` workflow to build or copy a place, serve on loopback and launch Studio with a one-session marker, guarded plugin installation and mandatory initial-sync confirmation. Preserve original places, existing output/plugin files and edited temporary places.

- Add explicit `textModule` sync rules for UTF-8 files, generating ModuleScripts that return exact text; support byte-preserving syncback/live writes of canonical literals and reject arbitrary code or incompatible layouts before writing. Existing CSV and text defaults remain unchanged.

- Add opt-in inherited `ignoreEmptyDirectories` filtering for implicit physically empty directory trees, preserving explicit bindings and file markers, and keeping live/watch trees current after last-file removal and recreation.

- Add opt-in `build --compress lz4|zstd|none` for binary outputs, including watch, stdin and existing-place updates, while retaining LZ4 defaults and rejecting explicit compression for XML before writing.

- Read project JSON/JSONC from stdin with `build -`, resolve sources from the current directory, and retain the in-memory project during watch builds without writing a temporary project file.

- Expose non-archivable `game.Rojo` discovery with per-plugin consent, scoped connection/status/settings/notification/context handles, explicit socket readiness and revocation/unload cleanup.

- Add opt-in Studio output forwarding with severity filters, bounded batches and current Lua source file/line mapping; stop forwarding on disconnect and retain compatibility with older servers/plugins.

- Accept project stems such as `game` for `game.project.json` or `game.project.jsonc` across project-reading CLI commands, retaining existing path precedence and output/input filenames.

- Use Open Cloud for existing model updates and place publishing, with API-key validation, model operation polling and correct binary content types; deprecate and ignore cookie authentication without reading installed cookies.

- Add `build --input` for scoped updates of existing binary/XML places, preserving unmentioned properties and unowned areas, maintaining references and replacing output only after successful serialization.

- Add `syncback --watch` with explicit repeated-write consent, coalesced input saves, recovery after incomplete input, fresh project reads and protection against overwriting its input.

- Add Cancel while connecting and stop pending startup work, preventing late responses or confirmation callbacks from applying changes, reconnecting or opening sockets after cancellation.

- Support nonempty directory arrays in `$path` for read-only sourcemaps, with canonical deduplication, recursive conflict-checked merges and watch regeneration across sources; build, serve and syncback reject array ownership.

- Add loaded-project `build_project` and typed `write_project` library APIs, preserving caller edits, reference resolution and the CLI serializers without starting a server.

- Add opt-in inherited `$ignoreUnknownDescendants` preservation with local metadata overrides, and warn with counts and paths before initial sync removes unknown Studio instances. Existing defaults and managed deletions are preserved.

- Accept unsigned 32-bit integer enum values in project, model and metadata properties, retaining named/qualified enums and rejecting invalid numeric values.

- Expose normalized source file paths on API reads with `?showPaths=true`, including embedded model children, while retaining the default response and public Rust structs.

- Add opt-in `sourcemap --relative-to-output` for output-directory-relative file paths, including watch mode, while preserving the default project-relative paths.

- Add opt-in `sourcemap --include-run-context` with reflected names and raw values for Script nodes, including property-only watch updates and default/unknown values. Existing class names and default output stay unchanged.

- Add `syncbackRules.ignoreClasses` for classes and derived classes: retain their existing disk subtrees and required ancestors, omit new excluded input, and preserve embedded model values and reference identities. Reject ambiguous or unsafe reference preservation before writing files.

## Deprecations

- Report an actionable error before attempting a legacy place upload, directing users to Open Cloud authentication.

- Cookie upload authentication is deprecated and ignored. The --cookie option emits guidance; Open Cloud --api_key is required. Installed cookies are no longer read.

## Fixes

- Validate server handshakes before reading protocol, session or capability fields, even when optional typechecking is disabled. Report malformed or undecodable replies with the server URL and connection guidance instead of a scalar-indexing exception.

- Keep additions whose managed parent is unavailable explicitly unapplied, including descendants, instead of throwing an invariant exception or creating orphans. Retain the subtree for retry and continue unrelated valid additions; report the missing parent context.

- Preserve inherited context for CSV snapshots without changing the CSV middleware. Keep custom CSV routes and instance identity on direct watch updates; apply inherited unknown-descendant preservation while retaining explicit metadata and shared-rule precedence.

- Remove deleted files and directory subtrees from their parent listings in the in-memory filesystem, matching native deletion and allowing clean recreation.

- Apply project ignore globs and negations to absolute source bindings outside the project directory, including wildcard rules on other drives. Retain project-relative `../` patterns on the same drive.

- Resolve relative syncback root directories from the project folder, preserving new children independently of the current working directory.

- Isolate serialized fallback models so one broken asset does not block healthy replacements; restore references, preserve failed changes, and retain legacy-server support.

- Disconnect when Studio changes to a place ID excluded by the connected project, reusing connection-time allow/deny checks and preventing further patch or write work; allowed and unrestricted ID changes remain connected.

- Stop patch-row animations and delayed expansion clicks after virtualized rows unmount, including removal during a height update, preventing Roact updates to destroyed UI.

- Skip queued tooltips whose trigger was removed during text measurement or virtualized scrolling, while continuing to render attached controls.

- Ignore repeated Connect actions and repeated session starts, preventing duplicate API connections and sync lock claims while allowing a fresh retry after immediate startup failure.

- Support explicit native Script/LocalScript metadata and faithful Lua syncback across emitter modes and script rules, preserving class, RunContext, source, children, IDs and existing Lua/JSONC paths; reject incompatible bindings and unsupported layout migrations before writes.

- Accept matching class declarations in project nodes and filesystem metadata while continuing to reject conflicting classes.

- Preserve Studio-only script descendants when toggling `emitLegacyScripts` for an unchanged, unambiguous script source.

- Avoid accumulating duplicate ignore rules when projects are re-snapshotted, preserving negation priority and each rule's base path.

- Support TweenInfo attributes using the local codec fork, preserving mixed attributes and avoiding repeated sync differences. Both server and plugin must support the negotiated extension.

- Preserve legacy MeshPart mass when binary output combines models with and without stored volume data.

- Keep live reference properties consistent with the final tree when targets are added, changed, removed, or ambiguous, and correctly apply explicit nil references.

- Avoid recurring plugin batcher errors for reference and unsupported property encoders; use tracked IDs for reference encoding and report untracked targets without blocking later source updates.

- Preserve parents of Init-named scripts and localization tables during syncback by using their directory representation for reserved filenames.

- Preserve existing directory contents and reject file collisions in memofs in-memory `create_dir_all`.

- Allow duplicate Studio-only children beneath project nodes without `$path` during syncback, while still rejecting ambiguous or missing managed children.

- Keep new children inside mapped model files during syncback instead of attempting to write paths beneath those files.

- Serialize syncback metadata and JSON-model properties and attributes in stable lexical order.

- Reject invalid Windows build output names instead of reporting successful builds into alternate data streams or device files.

- Report a contextual error for directory paths without a name, such as drive roots, instead of panicking during snapshot selection.

- Return a contextual API error when serializing an instance fails, keeping the serve session usable.

- Reject API writes with an actionable error if the change processor has stopped, instead of panicking on a closed channel.

- Report the source and project paths when syncback cannot determine the root path's middleware, instead of panicking.

- Preserve known instance identities when reconnecting to the same live server, so offline class changes and deletions do not leave stale or duplicate instances. Unknown-instance rules remain unchanged.

- Fixed delayed live-sync additions crashing after deletion or including later changes and duplicate children.

- Fixed syncback crashing when removing an embedded child from a model referenced by a project node.

- Fixed a subscription race that could leave connected clients waiting until another change arrived.

- Explain unexpected plugin disconnections with the server address and restart/reconnect guidance, retaining transport error details.

- Fixed plugin source updates writing to a directory instead of its init script, and publishing changes when writing the source failed.

- Return structured request errors instead of panicking when an API request body is aborted or cannot be read.

- Avoided redundant metadata patches for unchanged instances with `Rojo_Id` attributes.

- Fixed lost filesystem watches after failed registration or deletion and recreation of mapped directories.

- Fixed live-sync crashes when event targets or their parent directories disappear during rapid edits, and when the root source is temporarily removed.

- Reset removed properties in Studio through a negotiated live-sync extension, including reference properties, attributes, and tags. Both the server and plugin must support the extension.

- LocalizationTables no longer report as changed when nothing changes.

- Preserve a model root's snapshot identity through `$path` project layers so self references and child references resolve to the final managed root, including nested projects, aliased model sources and reloads.

- Report circular project references with their canonical path chain instead of overflowing the stack, while allowing independent aliases and later retries.

- Allow explicit `$path` bindings to init source files without importing sibling files, and avoid duplicate case-variant init children on Windows.

- Accept one leading UTF-8 byte order mark in JSON/JSONC projects, models, modules and metadata while preserving string contents and contextual parse errors.

- Sync immutable MeshPart mesh content through Roblox's mesh-loading API while preserving instance identity, children, transforms and texture; support live changes and removal for both `MeshContent` and legacy `MeshId`.

- Preserve Studio's active, unmanaged Workspace camera and viewpoint when connecting a fully managed project; explicitly managed cameras still follow project updates and deletions.

## Improvements

- Warn when a built place contains StarterCharacterScripts without StarterPlayerScripts. Inspect the final tree, including model sources, and document explicit typed container declarations without inserting instances or changing defaults.

- Warn with instance and property paths when live sync skips a requested unreadable property, including guidance for serialization-only place settings.

- Wrap the last-update control below the version header in narrow plugin panels, returning to a single row when widened and accounting for longer prerelease version labels.

- Add a failures-only patch view with ancestor paths and failed properties, allowing quick inspection among many successful changes and a return to the full change list.

- Warn with file and node paths for ignored model/metadata fields, including a correction for project-style `$properties`; retain supported tag handling and JSONC metadata paths.

- Bound HTTP API request bodies to 64 MiB by default, with a positive `serve --max-request-body-bytes` override and structured HTTP 413 errors before parsing oversized bodies.

- Batch rapid `build --watch` changes into a bounded collection window to avoid exporting once per changed file.

- Warn at session startup when the root project maps the same canonical `$path` to multiple nodes, retaining intentional aliases.

- Added opt-in filesystem operation and watcher diagnostics through the `memofs` log target.

- Include active filesystem event, project, and build output paths in crash diagnostics.

- Remove large instance batches with one stable sibling-list filter per parent, preserving metadata, references and surviving instance order through the local DOM fork.

- Match large groups of snapshot children through ordered name/class candidate lists, avoiding repeated sibling scans while preserving duplicate and script-source identity rules.

- Fork update checks and user-facing failure links point to jonasvq/rojo. CLI and Studio plugin report8.0.0; rokit.toml pins jonasvq/rojo@8.0.0.

## Compatibility and upgrade guidance

- Install this fork's 8.0.0 CLI and matching Studio plugin together. The VSCode
  extension has its own version history.
- Protocol 5 stays in use. Property removals, TweenInfo attributes, Source receipts,
  class authority and other extensions negotiate capabilities. Incompatible
  authority sessions are rejected before unsafe sync.
- Existing unversioned/V1 projects retain their defaults. Explicit V2 selects
  modern Script RunContexts and unknown-descendant preservation; explicit
  overrides still win. Review effective settings when opting in.
- Source receipts distinguish queued work from applied/unchanged readback.
  Conflicting or uncertain writes retain review requirements.
- Class-authority changes and destructive replacements require review before
  discarding Studio-owned values. Explicit saved-file syncback applies the
  selected filesystem/Studio policy and checks structure/reference safety.
- Public Rust CLI command structs gained options for the new workflows.
  Core library consumers retain documented re-exports and can opt out of CLI
  dependencies through default-features=false.
- Source build and Studio acceptance are distinct checks; a successful build
  parses/serializes a project without executing gameplay.
